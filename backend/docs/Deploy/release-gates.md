# Release gates

Itemize has two release gates. Run both from the repository root before a production deployment that changes application code, GraphQL contracts, migrations, or background jobs.

## Static release gate

```bash
npm run release:check
```

This gate verifies:

- documentation mirrors are current;
- the retained Express REST inventory and GraphQL cutover ledger have not drifted;
- every runtime variable read by `backend-v2` is declared in its environment contract;
- every statically declared frontend GraphQL operation validates against the schema generated by Nest;
- Express, Nest, and frontend production builds complete;
- the frontend bundle remains within its size budget.

GraphQL operations must be static, named documents. Shared selection strings are supported, including imports. Do not construct operation or field names through runtime string interpolation because those requests cannot be checked before deployment.

## Fresh-database integration gate

```bash
npm run release:integration
```

This gate creates an isolated disposable PostgreSQL instance, initializes the complete migration stream, runs the legacy and Nest integration suites, and removes the disposable database afterward. It never targets the normal local or production database.

Run this gate whenever a migration, repository, scheduler, delivery worker, ownership flag, or database-backed resolver changes. Runtime-specific troubleshooting is also available:

```bash
node backend/scripts/run-integration-tests-fresh.js --legacy-only
node backend/scripts/run-integration-tests-fresh.js --nestjs-only trial-reminders.integration-spec.ts
```

## Deployment order

1. Run `npm run release:check`.
2. Run `npm run release:integration` when the database-backed scope above applies.
3. Apply required migrations while the existing runtime still owns its workers.
4. Deploy application code with new Nest workers disabled.
5. Transfer each worker using the ownership sequence in `runtime-and-worker-ownership.md`.
6. Verify health, queue age, error rate, and one representative user flow before enabling the next worker.

## AI suggestion launch gate

When prompts, providers, model configuration, suggestion UX, or AI limits change, also run the paid comparison gate documented in `Product/ai-suggestion-launch-audit.md`. This gate is manual by design and does not run inside `release:check`.
