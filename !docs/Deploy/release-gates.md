# Release gates

Itemize has two release gates. Run both from the repository root before a production deployment that changes application code, GraphQL contracts, migrations, or background jobs.

## Static release gate

```bash
npm run release:check
```

This gate verifies:

- documentation mirrors are current;
- retained Nest HTTP and GraphQL authorization/consumer contracts have not drifted;
- every checked runtime variable read by `backend` is declared in its environment contract;
- every statically declared frontend GraphQL operation validates against the schema generated by Nest;
- Nest and frontend production builds complete;
- the frontend bundle remains within its size budget.

GraphQL operations must be static, named documents. Shared selection strings are supported, including imports. Do not construct operation or field names through runtime string interpolation because those requests cannot be checked before deployment.

## Fresh-database integration gate

```bash
npm run release:integration
```

This gate creates an isolated disposable PostgreSQL instance, initializes the complete migration stream, runs the Nest integration suites, and removes the disposable database afterward. It never targets the normal local or production database.

Run this gate whenever a migration, repository, scheduler, delivery worker, ownership flag, or database-backed resolver changes. Runtime-specific troubleshooting is also available:

```bash
node db/scripts/run-integration-tests-fresh.js trial-reminders.integration-spec.ts
```

## Deployment order

1. Run `npm run release:check`.
2. Run `npm run release:integration` when the database-backed scope above applies.
3. Let the fail-closed API pre-deploy migration gate apply migrations; review compatibility with running and rollback images.
4. Deploy tested code while preserving established Nest worker flags. There is no legacy owner to transfer from.
5. For a new worker, inspect backlog, provider configuration and overlap behavior before enabling it. Follow `runtime-and-worker-ownership.md`; do not launch duplicate one-shot jobs.
6. Verify the deployed commit, health, queue age, error rate and one representative flow. CI additionally runs frontend lint, unit tests, fresh database integration and the production dependency audit; release:check alone does not include these checks.

## AI suggestion launch gate

When prompts, providers, model configuration, suggestion UX, or AI limits change, also run the paid comparison gate documented in `Product/ai-suggestion-launch-audit.md`. This gate is manual by design and does not run inside `release:check`.
